두 목표가 서로를 밀어냅니다

이벤트의 목적은 리뷰 수인데 선별의 목적은 리뷰 질입니다. 기준을 올리면 수가 줄어듭니다.

이벤트가 원하는 것

리뷰 수입니다.
상점마다 리뷰가 일정 수 이상 쌓여야 검색 결과가 채워지고, 비어 있는 상점은 이용자에게 선택지가 되지 못합니다.

선별이 하는 일

기준에 못 미치는 리뷰를 걸러냅니다.
품질은 올라가지만 노출되는 리뷰 수는 줄어들고, 걸러진 작성자는 보상을 받지 못해 불만이 됩니다.

보상 시점을 옮기면 충돌이 사라집니다

지금은 쓰면 보상이고 그 뒤에 걸러냅니다. 작성자는 보상만 노리고 운영자는 걸러내는 데 시간을 씁니다.

채택될 때 지급으로 바꾸고 기준을 미리 공개하면 작성자가 스스로 거릅니다. 걸러내는 작업 자체가 줄어드는 것이 핵심입니다.

수량도 함께 지키는 방법

보상을 둘로 나눕니다. 기본 조건이면 소액, 채택되면 추가입니다. 문턱이 낮아 수는 확보되고 추가분이 품질을 끕니다. 하나의 보상으로 둘을 다루면 반드시 한쪽을 잃습니다.

퀘스트 조건이 새로운 저품질을 만듭니다

미션 예시는 인증샷 3장과 꿀팁 50자입니다.
참여 동선을 명확하게 만드는 데는 효과적인데, 게임 운영에서 익숙한 부작용이 따라옵니다.

조건을 정하면 조건만 채웁니다

50자가 기준이면 정확히 50자짜리 빈 글이 나오고, 사진 3장이 기준이면 각도만 바꾼 3장이 올라옵니다. 기준을 형식으로 정하면 형식만 채워집니다.

형식은 최소 자격으로만 두고, 채택 판정은 결과 기준으로 옮깁니다. 도움이 됐다고 표시한 수, 리뷰를 보고 상점을 저장한 비율 같은 값입니다. 작성자가 조작하기 어렵고 실제로 도움이 된 것만 남습니다.

사진 도용은 형식 검사로 잡히지 않습니다

문제 정의에 사진 도용이 들어 있는데 대응이 명시되지 않았습니다.
도용 사진도 사진이므로 인증샷 3장 조건을 통과합니다.
별도 검사가 필요한 항목입니다.

  • • 중복 이미지 검출 — 이미 등록된 사진과 같은 이미지인지 대조합니다. 다른 상점이나 다른 작성자의 사진을 가져온 경우가 여기서 잡힙니다
  • • 촬영 정보 확인 — 촬영 시각이 방문 시점과 맞는지 봅니다. 다만 메타데이터는 편집이나 전송 과정에서 사라지므로 없다는 것만으로 도용으로 판정하면 안 됩니다. 보조 지표로만 씁니다
  • • 위치 대조 — 업로드 시점의 위치가 상점 위치와 크게 다르면 우선 검토 대상으로 분류합니다

세 항목 모두 판정이 아니라 볼 순서를 매기는 용도로만 씁니다. 정상 이용자가 도용으로 걸리면 그 손실이 저품질 리뷰 몇 건보다 큽니다.

수치를 쓰지 않은 것에 대해

절감 폭을 숫자로 적지 않았습니다. 확인되지 않은 값을 지어내지 않았기 때문입니다.

대신 무엇을 어떻게 잴지를 적었습니다. 리뷰 1건당 검수 소요 시간을 도입 전후로 재면, 지금 없는 데이터를 요구하지 않으면서 개선을 증명할 수 있습니다.

측정할 지표

  • • 리뷰 1건당 검수 소요 시간 — 자동 선별 도입 전후 비교. 대폭 단축이라는 서술을 숫자로 바꾸는 값입니다
  • • 이벤트 리뷰의 채택률 — 작성된 리뷰 중 품질 기준을 통과한 비율. 보상 구조를 바꾼 효과가 여기서 나타납니다
  • • 리뷰 수와 채택 수를 함께 — 채택률만 오르고 총 수가 줄면 이벤트 목적을 잃은 것입니다
  • • 도움됨 반응 비율 — 형식 요건이 아니라 결과 기준으로 품질을 보는 지표입니다
  • • 도용 판정 정확도 — 우선 검토로 올린 건 중 실제 도용 비율. 낮으면 정상 이용자를 괴롭히는 것입니다
