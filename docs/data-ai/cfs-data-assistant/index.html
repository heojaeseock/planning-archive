도전 2. 개발자 없이 복잡한 DB 데이터 추출 (SQL)

목표: 일상적인 비즈니스 언어로 된 요청을 해석하여 정확한 SQL JOIN 쿼리로 변환 및 실행

Situation: 매니저의 긴급 데이터 추출 요청
"재석님, 이번 주 출고 지연된 건 중에서 서울 센터 물량만 센터명과 상품아이디 포함해서 리스트 뽑아주세요!"
[보유 스키마 정보]
- Orders Table: id, item_id, center_code, status
- Centers Table: center_code, center_name, region
👇 클릭 한 번으로 쿼리 생성
🔒 AI를 통해
DB를 조회하세요
After: 쿼리 생성 결과
▶ 도출된 쿼리문:
SELECT o.id, o.item_id, c.center_name 
FROM Orders o
JOIN Centers c ON o.center_code = c.center_code
WHERE o.status = 'Delayed' 
  AND o.center_code = 'SEL';

받은 답을 검증하는 단계

받은 답이 요구와 맞는지 대조하는 단계가 붙어야 실무가 됩니다. 두 사례에서 실제로 조건이 빠져 있었습니다.

사례 1 · 엑셀 수식

일별 추이가 빠졌습니다

요구는 일별 추이인데 나온 수식은 전체 기간 총 건수를 셉니다.

=COUNTIFS($D:$D,"에러",$C:$C,"",$A:$A,기준일)

입고일이 있는 A열을 조건에 넣어야 추이가 나옵니다. 건수가 많으면 피벗 테이블이 빠릅니다.

사례 2 · SQL 쿼리

이번 주가 빠졌습니다

기간 조건 없이 전체가 나옵니다. 원인은 다릅니다 — 준 스키마에 날짜 열이 없었습니다.

하나는 AI가 놓친 것이고 하나는 내가 덜 준 것인데, 결과는 같습니다. 조건이 빠진 채 아무 경고 없이 돌아옵니다.

여기서 실력이 갈립니다

둘 다 겉으로는 정상입니다. 수식은 숫자를 내고 쿼리는 행을 돌려줍니다. 빠진 조건은 한 줄씩 맞춰볼 때만 드러나고, 그러려면 수식과 쿼리를 읽을 줄 알아야 합니다.

그래서 개발자 없이가 아니라 개발자를 기다리지 않고입니다. 도구를 쓰는 능력과 답을 검수하는 능력은 별개입니다.

그 밖에 함께 확인한 것

· 빈칸의 정의 — 빈 문자열 조건은 진짜 빈 셀과 수식 결과가 빈 셀을 함께 셉니다

· 불량률의 분모 — 일별로 보려면 분모도 일별 입고 건수여야 합니다. 전체 52,140건을 쓰면 추이가 눌립니다

· 센터 코드 — 쿼리가 코드를 추측해 박았습니다. 지역 열로 걸러야 센터가 늘어도 돕니다

· 이번 주의 기준 — 월요일 시작인지 최근 7일인지에 따라 결과가 달라집니다. 날짜로 되물어 확정합니다

사례마다 무엇을 보는지 정해 두었습니다

세 사례는 위험의 종류가 다릅니다. 실행 전에 볼 것을 미리 정해 뒀습니다.

SQL 추출

틀려도 결과가 나옵니다

쿼리가 틀려도 오류 없이 그럴듯한 목록이 나옵니다. 그대로 올리면 판단에 들어갑니다.

  • · 건수 대조 — 이미 아는 값과 맞춥니다. JOIN이 잘못되면 행이 부풀어 여기서 잡힙니다
  • · 조회 부하와 권한 — 운영 DB 대량 스캔은 서비스에 영향을 줍니다. 조회 전용 환경을 씁니다

영문 보고

숫자와 이름이 바뀌면 사고가 됩니다

새벽에 임원에게 바로 가는 보고라 검토할 사람이 없습니다.

  • · 숫자 대조 — 단말 50대, 지연 45분, 복구 목표 7시. 셋만 맞춰도 대부분 막힙니다
  • · 확정과 예정의 구분 — 커버 가능은 예상이고 정상화는 완료입니다. 영문에서 섞이면 사실이 달라집니다
  • · 책임 서술 — 원인 규명 전에는 현상과 조치만 적습니다

AI에게 무엇을 주었는가가 결과를 갈랐습니다

조건으로 분해

막연한 요청을 열과 값 기준 조건으로 바꿔 전달했습니다. 이 분해 없이는 수식이 나오지 않습니다

스키마 제시

테이블과 컬럼 구조를 먼저 줬습니다. 없으면 존재하지 않는 컬럼을 쓴 쿼리가 나옵니다

보고 대상 지정

외국인 임원 대상이라는 조건으로 문체와 구조가 정해졌습니다

절감 배수가 세 작업 모두 같습니다

작업 수동 도구 활용 절감 배수
엑셀 조건 검색과 정제 45분 3분 42분 15.0배
DB 쿼리 작성 60분 4분 56분 15.0배
글로벌 보고 작성 30분 2분 28분 15.0배

성격이 다른 세 작업이 똑같이 15배입니다

필요한 기술도 걸리는 이유도 다른 세 작업인데 절감 배수가 모두 정확히 15배입니다. 45와 3, 60과 4, 30과 2로 떨어지는 정수이기도 합니다. 실제로 잰 값이 이렇게 맞기는 어렵습니다.

수동 시간은 추정값입니다. 작업 하나라도 실제로 재 두면 나머지 추정에 근거가 생깁니다. 총 절감 시간보다 그 기록 하나가 셉니다.

저장해서 다시 쓰면 배수가 크게 떨어집니다

수식과 쿼리는 한 번 만들면 저장해 두고 다시 씁니다. 같은 작업을 열 번 한다고 놓으면 이렇게 갈립니다.

엑셀 수식 열 번

매번 새로 만들면 450분, 저장해 두고 조건만 바꾸면 90분, 도구를 쓰면 30분입니다. 저장 습관이 있는 사람에게는 3배입니다.

쿼리 열 번

같은 방식으로 600분, 105분, 40분입니다.
배수가 15배에서 2.6배로 내려갑니다.

그래서 이 도구의 값어치는 반복이 아니라 처음에 있습니다

매번 같은 일이면 저장해 두는 것으로 충분합니다. 도구가 크게 이기는 구간은 처음 만나는 조건입니다. 반복 업무 자동화가 아니라 비정형 요청 대응입니다.
